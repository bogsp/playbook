# Edit Template Source

---

## What It Does

Changes a file under `playbook/.playbook/` or `playbook/docs/` — the
domain-agnostic source that `create-playbook` copies into every new
project's scaffold. Distinct from editing this repo's own `.playbook/`,
which governs this repo's sessions and is never shipped.

## Before It Starts

The target file is confirmed to live under `playbook/` (not root `.playbook/`
or `docs/`, which belong to this repo's own meta-pipeline). The person or AI
has a specific, scoped change in mind — not a speculative or exploratory
edit.

## When It Finishes

The template source file reflects the intended change. The edit has been
recognized as a product change — per `.playbook/AI-INSTRUCTIONS.md` rule 2,
what changes for every future scaffolded project has been stated, not just
what changed in the file. `packages/create-playbook/templates/` has **not**
been touched — it is a build artifact, untouched until `flow-2` runs.

## Walkthrough

This flow is manual editing, not code execution — the steps below describe
the discipline around the edit, not a function call sequence.

---

```
1. On [Template Change Request](target file, intended change):
   a. confirm target path is under playbook/.playbook/ or playbook/docs/
      → ok: [confirmed template file]        → continue to b
      → err: file is under root .playbook/   → this is a meta-pipeline edit,
                                                 not a template edit — halt,
                                                 redirect to the correct track
   b. edit the file directly — content change only, no rebuild yet
      → ok: [file updated]                   → continue to c
   c. state the product impact — what changes for every future
      create-playbook init going forward
      → ok: [impact stated]                  → continue to d
   d. check whether packages/create-playbook/build.js's `sources` array
      needs a new entry
      → new file added to playbook/          → yes: add matching entry
                                                 → continue to flow-2
      → existing file edited only            → no source-list change needed
                                                 → continue to flow-2
```

---

## Detail

- This flow never writes to `packages/create-playbook/templates/` — that
  directory is fully regenerated by `flow-2-build-and-publish`, and hand
  editing it is explicitly prohibited by `.playbook/AI-INSTRUCTIONS.md`
  rule 1.
- Step d is the coupling point with the build step: `build.js` maps each
  source file to a destination path via a hardcoded `sources` array. A new
  template file with no matching array entry will silently never reach
  `templates/` — `flow-2` has no way to detect a missing intended file, only
  a missing existing one (it errors on files it expects but can't find).
- Editing this repo's *own* `.playbook/` (session rules, kit files, repo map)
  is out of scope for this flow entirely — see `.playbook/AI-INSTRUCTIONS.md`
  for that track instead.
