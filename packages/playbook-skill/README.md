# @bogsp/playbook-skill
# File: packages/playbook-skill/README.md

A Claude Skill that scaffolds a Playbook project directly inside a Claude
session — the same output as `create-playbook`, without leaving the chat to
run a CLI command.

---

## What This Is

`create-playbook` is the tool-agnostic entry point — it works from any
terminal, for anyone using any AI tool. This skill is a second, additive
entry point specifically for people already working in Claude Code, Claude
Desktop, or Cowork: say "set up a new Playbook project here" and Claude reads
[SKILL.md](SKILL.md), asks the same setup questions the CLI asks (domain,
project type, review-gate level, pipeline mode), and writes the scaffold
itself.

Neither entry point is more "correct" than the other — they produce
equivalent output from the same source.

## Building

`assets/` is a **build output**, generated by [build.js](build.js) from
`playbook/.playbook/` and `playbook/docs/` — the exact same source tree
`packages/create-playbook/build.js` reads from. Never hand-edit anything
under `assets/`; fix the source in `playbook/` and rebuild:

```bash
cd packages/playbook-skill
pnpm build
```

Run this once before first use, and again any time `playbook/.playbook/`
changes in a way the skill should pick up. `assets/` is committed (the Skill
is installed from a clone), so it is guarded by a drift check: run
`pnpm check:drift` from the repo root — it fails if `assets/` differs from a
fresh build, which means someone changed the template and forgot to rebuild.

Which files get copied is defined once, in
[`../template-manifest.json`](../template-manifest.json), shared with
`create-playbook`. There is no second list to keep in sync.

## Installing

Where you install it depends on how you want to use it. In every case, only
`SKILL.md` and `assets/` are needed at runtime — `build.js`, `package.json`,
and this README are source-maintenance files, not part of what Claude reads.

### Claude Code — personal (available in every project)

Recommended for general use, since scaffolding a new Playbook project
happens in whatever repo you're starting, not just this one. A symlink
means future edits to the source apply automatically — nothing to re-copy.

```bash
mkdir -p ~/.claude/skills
ln -s /absolute/path/to/playbook/packages/playbook-skill \
  ~/.claude/skills/playbook-scaffold
```

### Claude Code — project only (this repo)

Use this instead if you only want the skill available while working inside
the Playbook repo itself (e.g. for contributors who clone this repo):

```bash
mkdir -p .claude/skills
ln -s ../../packages/playbook-skill .claude/skills/playbook-scaffold
```

### Claude.ai, Cowork, or the Desktop app

These don't read local folders — enable the skill from your account
instead: Desktop app → **Customize** sidebar, or the skill settings on
claude.ai. Upload the `packages/playbook-skill` folder (or just
`SKILL.md` + `assets/`) there directly.

That upload path only accepts `name`, `description`, `license`,
`compatibility`, `metadata`, and `allowed-tools` in the frontmatter — this
skill's `SKILL.md` only uses `name` and `description`, so it works there
without changes.

### Verifying it loaded

In Claude Code, run `/skills` and confirm `playbook-scaffold` is listed.
Then try: *"Set up a new Playbook project here."*

## Structure

```
packages/playbook-skill/
  SKILL.md              — instructions Claude reads when the skill triggers
  build.js               — generates assets/ from playbook/.playbook/ + playbook/docs/
  assets/                 — BUILD ARTIFACT — generated, never hand-edited
    universal/
      playbook/            — _index.md, rules.md, README.md, pipeline.md, maintenance.md,
                              expansions.md, adopt.md, audit.md, templates/
      kit/                  — the kit file templates + _tests/test-case.md
      docs/                 — flow-template.md, contract-template.md, global.md,
                              rewrite templates
    software/ | writing/ | production/ | manufacturing/
      vocabulary/
        _index.md            — combined vocabulary + AI rules for that domain
        templates/            — domain-specific planning-doc shapes
  package.json
  README.md               — this file
```
