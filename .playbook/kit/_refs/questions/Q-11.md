# Q-11: Proactive Onboarding, Progressive Disclosure & Opt-In Orchestration

## Core Direction
1. **Get out of the way at session start:** Do not stall users with rigid turn-1 gates or walls of pipeline jargon. Confirm loaded state briefly, let the user jump straight into their project, and guide them based on their responses and cues.
2. **Progressive disclosure over existing pipeline stages:** Use Playbook's existing stages (`Thinking -> Discovery -> Mapping -> Rules -> Planning -> Work -> Handoff`, plus `Audit`), modes (`kit-only` vs. `full`), and `review-gate` as optional structure surfaced only when conversational cues or project complexity warrant it (active only once Playbook is loaded/present in the project).
3. **Integrate Playbook into existing orchestration (not vice versa):** Do not compete with users' agent runners or tie Playbook to paid AI services. When users already run lead/follower (or lead/worker) agents, those agents follow Playbook's stages, rules, and brief/handoff standards across any domain (software, writing, operations, manufacturing).

## Discovery & Activation Findings
- **Session discovery:** Playbook guidance activates only when Playbook context is loaded (via the landing page start flow, `.playbook/_index.md`, `rules.md`, or repo pointers like `AGENTS.md`/`CLAUDE.md` or optional `SKILL.md`), never guessed in a cold zero-context chat.
- **Agent orchestration discovery:** Users' lead agents keep ownership of spawning/routing workers and embed a compact Playbook standard block (stage/mode, scope boundaries, governing rules/contracts, acceptance criteria, and factual report expectations) inside worker briefs.

## Forgetfulness Resilience & Embedded AI Directives
- **User forgetfulness is expected:** The AI proactively maintains or proposes updates to kit files, plans, flows, and contracts when relevant cues occur instead of relying on the user to remember.
- **Quiet transparency:** Guidance stays low-friction and never "in-your-face," while making state changes and stage triggers explicit and visible.
- **Embedded core instructions:** Core AI directives live directly in `.playbook/_index.md` (and guide workflows) so behavior holds across sessions without requiring extra setup.

## House Rules & Emergent Preferences (`X1`, `X2`, …)
- **Explicit methods & recurring patterns:** The AI captures explicit user methods/constraints immediately as project rules (`X1`, `X2`, …) in `_index.md` under **Project Rules**, and proposes new `X` rules when a clear preference repeats across turns.
- **Boundary with core rules:** Project house rules customize execution for that repo without altering universal Playbook rules in `rules.md`.
