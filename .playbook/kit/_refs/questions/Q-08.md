Q-08: Should Sage's parallel-lane protocol become a Playbook feature?

Sage runs up to three tickets at once (Project Sage repo (bogsp/sage), D116, amended by D117): each ticket declares an `owns:` write-set; claiming is a pushed one-line kanban commit; every ticket works on `main` with `git pull --rebase` before push (D117 dropped lane branches and PRs); lane state lives on one line per lane in `01-process.md`.

Playbook's own roadmap (`docs/playbook-autonomous-rollout-roadmap.md`, parallel phase) says to introduce parallel work only after the sequential system is reliable and to keep agents off the same shared state. Sage's rollout is evidence for that phase, including what went wrong: shared kit files are the conflict hotspot, and a Free-plan private repo has no branch protection to enforce any of it.

Open: ship the protocol as an expansion, as rules, or keep it a Sage practice. Not decided.
