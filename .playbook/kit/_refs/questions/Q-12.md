# Q-12: Project Upgrade & Migration Workflow

## Problem
Upgrading an existing project to a newer Playbook version/implementation risks overwriting project identity, tracking history, or custom house rules (X1, X2, ...), or forcing manual file-by-file diffs.

## Candidate Approaches
- CLI upgrade command in create-playbook using template-manifest.json and version stamps (links with K-58, K-59, K-62).
- Guided AI upgrade pass that updates framework files, preserves X rules and kit history, and flags conflicts transparently.
- Explicit file classification (replace-safe vs. merge-careful vs. project-owned).
